An agent that sells flowers over Instagram DMs.

Petals & Blooms is a TypeScript sales agent: a router decides what the customer needs and hands off to a specialised generator node, wired to Gemini, the Instagram Graph API and Stripe.

The real work was the failures. It dodged when asked for a price. It carried one customer's details into another's chat. It promised flowers it had not checked were in stock. It sent a checkout link before anyone had agreed to buy. Fixing those four taught me more about agents than building the first version did.

2025 · Side project

An agent that trades.

NEXUS is a trading system on Binance, connected over WebSocket and REST. It runs one loop without stopping: scan, plan, execute, monitor, review.

Each trade passes a 7-stage decision engine that reads chart patterns, Smart Money Concepts and VWAP. The risk limits live on the server, where the agent cannot talk itself out of them. 79% win rate across about 71 trades.

What I've been working on.

Agents for a multi-tenant B2B automation platform, the graph they reason over, and the data layer underneath. I lead the research team and still build hands-on.

One idea runs through all of it: an agent should be able to say why it did something, and be stopped before it does the wrong thing. So the reasoning lives where it can be checked, and every action passes a gate first.

I also write the specs, including a 12,700-word design for an experimentation engine and a goal-linked spec language and benchmark for UI/UX generation.

01

A knowledge graph that reasons inside the databaseReasoning runs as SQL, on YugabyteDB

A neurosymbolic hypergraph on YugabyteDB where reasoning runs as SQL functions: an ontology-typed graph, symbolic filters before HNSW vector search, geometric scoring over 1024-d embeddings, causal path enumeration, and Bayesian belief propagation with Thompson Sampling bandits.

02

Reasoning you can auditFormal contracts gate every agent action

Formal contracts and state-machine model checking gate every agent action and record how it was justified. Conclusions are invalidated when their sources change. Graph branching allows what-if reasoning, and an LLM planner's query plans are validated before they run.

03

Documents into knowledgeA 7-layer RAG pipeline for 100+ page documents

A 7-layer, ontology-aware RAG pipeline that ingests 100+ page documents: two agents deliberating on LangGraph, graph-aware deduplication, rule extraction and strict source grounding, measured on recall and cycle consistency.

04

An agent platform that refuses by defaultPolicy engine, undo receipts, five-level autonomy

Every read and write goes through a policy engine. Commands are transactional and can be undone through receipts. The assistant runs on a five-level autonomy ladder defined in the ontology itself.

05

One data layer for every channel24 schemas, 140+ tables, event-sourced CQRS

24 schemas, 140+ tables, 130+ functions and 8 state machines on an event-sourced CQRS design: conversation threading, contact identity, consent, sequences, lead scoring and audit trails. Plus a wider platform design of 128 tables with row-level security and CDC ingestion.

06

Agents that hold conversationsA DM agent on six platforms and a real-time voice agent

A FastAPI and LangGraph service running DMs across LinkedIn, Instagram, X, Reddit, Facebook and WhatsApp, and a real-time outbound voice agent on Telnyx, Deepgram and Gemini Flash — integrated with zero new schema objects.

07

Proof, not vibesDifferential testing: 159/159, 450/450, 801/810

Rebuilt a rule engine in PL/pgSQL and differentially tested it against the original: 159/159, 450/450 and 801/810 across stages. Also an LLM-driven SQL certification pipeline with Gemini 2.5 Pro and the Z3 solver.
